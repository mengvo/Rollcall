RollcallApp.swift — This is the entry point of the entire app. The @main attribute tells iOS "start here." All it does is launch a window and put ContentView inside it. Think of it like main() in Python or C.

ContentView.swift — This is the main screen the user sees. It layers three things on top of each other using a ZStack: the live camera feed on the bottom, the green face-detection rectangles in the middle, and the UI controls (capture button, results list, loading spinner) on top. It owns the app's main state — the list of identified people and whether we're currently processing. When you tap the capture button, it tells CameraManager to snap a photo, sends that photo to APIService for identification, and updates the UI with the results.

Models.swift — The data structures. IdentifiedPerson represents someone your backend recognized (has a name, ID, and confidence score). DetectedFace represents a face that Apple's Vision framework found in the camera feed (just a bounding box rectangle, no identity yet). These are the "nouns" of your app — everything else passes these around.

CameraManager.swift — This is the heaviest file and does two jobs. First, it sets up the camera hardware: creates an AVCaptureSession, connects the physical camera as input, and attaches two outputs (one for live video frames, one for taking photos). Second, it runs face detection: every time a new video frame comes in, it feeds that frame to Apple's VNDetectFaceRectanglesRequest, which returns the coordinates of any faces it finds. Those coordinates get published to detectedFaces, which the UI observes. It also handles the one-off photo capture when you tap the button — it takes the photo, converts it to a UIImage, and passes it back via a callback.

CameraPreviewView.swift — SwiftUI can't directly display an AVCaptureSession camera feed, so this file bridges that gap. It wraps a UIKit UIView with an AVCaptureVideoPreviewLayer attached to it. That layer takes the raw camera stream and renders it visually. The UIViewRepresentable protocol is the standard way to embed UIKit views inside SwiftUI. Without this file, you'd have all the camera logic working but nothing visible on screen.

FaceOverlayView.swift — This draws the green rectangles around detected faces. It takes the list of DetectedFace objects from CameraManager and, for each one, draws a green Rectangle stroke at the right position. There's a coordinate conversion happening here because Apple's Vision framework uses a coordinate system where (0,0) is the bottom-left and values go from 0 to 1, but SwiftUI puts (0,0) at the top-left and uses pixel values. The convertBoundingBox function handles that translation.

PeopleListView.swift — The results UI that slides up from the bottom after you capture and identify. It's a horizontal scrollable row of cards, one per identified person, showing their initial in a circle, their name, and the confidence percentage. It uses .ultraThinMaterial for that frosted-glass look over the camera feed. This only appears when identifiedPeople is non-empty.

APIService.swift — The networking layer that talks to your FastAPI backend. It has one method: identifyFaces(in:). It takes a UIImage, compresses it to JPEG, wraps it in a multipart form-data HTTP request (the same format as an HTML file upload form), and POSTs it to your backend's /identify endpoint. When the response comes back, it decodes the JSON into an array of IdentifiedPerson objects. The baseURL is hardcoded to localhost:8000 right now — you'll need to change that to your actual server address when testing on a real device, since localhost on an iPhone doesn't point to your Mac.
The data flow in a nutshell: Camera hardware → CameraManager feeds frames to Vision → DetectedFace boxes drawn by FaceOverlayView → user taps capture → CameraManager snaps photo → APIService sends it to FastAPI → backend returns [IdentifiedPerson] → ContentView updates state → PeopleListView renders the results.
